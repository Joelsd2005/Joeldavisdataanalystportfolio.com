Sega Game Performance Dashboard

Development Process & Project Case Study

This project examines Sega video game performance using descriptive analytics and interactive data visualisations. The analysis explores game releases, platforms, genres, developers, Metacritic scores and user ratings. I developed the analytical dashboard in Power BI and recreated it as an interactive website for my data analyst portfolio.

Tools: Power BI Desktop, Power Query, DAX, HTML, CSS, JavaScript, Chart.js and GitHub Pages.
Project type: Data cleaning, descriptive analytics, relational data modelling, dashboard development and interactive web visualisation.

1. Importing and Understanding the Dataset

I began by importing SegaGames.csv into Power BI Desktop using Home, Get Data and Text/CSV. The dataset contains 1,481 game-platform records and 875 distinct game titles.

The dataset includes the following fields:

  • Game title
  • Platform
  • Release date
  • Metacritic score
  • User score
  • Developers
  • Genres
  • ESRB rating
  • Game information link

I reviewed the dataset to identify missing values, confirm appropriate data types and prepare the information for analysis.

2. Data Cleaning in Power Query

I used Power Query to transform the original dataset into a format suitable for Power BI.

  1. Checked that Metacritic and user scores were stored as numeric values.
  2. Preserved missing review scores as null values rather than replacing them with zero.
  3. Converted the release date into a suitable date format.
  4. Created a Release Year column to support time-series analysis and filtering.
  5. Applied Trim to text fields such as genres and developers to remove unnecessary spaces.

Creating the Release Year Column

I extracted the release year from the original date column to examine game performance over time. 

Date.Year([date])

This Power Query expression extracts the year from a date value.

3. Preparing Genre and Developer Data

Some records contained multiple genres or developers within a single field. To analyse these categories individually, I created separate reference queries from the original SegaGames table.

Genre Table

  1. Created a reference of the SegaGames query.
  2. Renamed the query SegaGenres.
  3. Kept the Game ID and genres columns.
  4. Removed unnecessary brackets and quotation marks.
  5. Split comma-separated genres into individual rows.
  6. Trimmed spaces and removed blank genre values.

Developer Table

I followed a similar process to create the SegaDevelopers reference table, allowing individual developers to be used in dashboard filters without duplicating records in the original fact table.

4. Creating the Data Model

I added a unique Game ID index to the original SegaGames table before creating the reference queries. This allowed the supporting tables to retain matching identifiers.

The model contains three main tables:

  • SegaGames: Original game-platform records and numerical performance measures.
  • SegaGenres: Individual genres linked by Game ID.
  • SegaDevelopers: Individual developers linked by Game ID.

I connected SegaGames to each supporting table using one-to-many relationships based on Game ID. Bidirectional filtering was used where required so genre and developer slicers could filter the dashboard's measures and charts.

5. Creating KPI Measures with DAX

I created four key performance indicators to summarise Sega's game portfolio.

Total Games

Total Games =
DISTINCTCOUNT('SegaGames'[title])

Counts unique game titles, preventing repeated titles across different platforms from inflating the total.

Total Platforms

Total Platforms =
DISTINCTCOUNT('SegaGames'[platform])

Counts the number of distinct platforms represented in the dataset.

Average Metacritic Score

Average Meta Score =
AVERAGE('SegaGames'[meta_score])

Calculates the average critic score across records containing valid numerical scores.

Average User Score

Average User Score =
AVERAGE('SegaGames'[user_score])

Calculates the average consumer rating, excluding blank scores.

6. Building the Dashboard Visualisations

I developed four visualisations to explore different aspects of Sega game performance.

Games by Platform

A horizontal bar chart compares the number of distinct game titles across different gaming platforms.

Metacritic Score vs User Score

A scatter chart examines the relationship between professional critic scores and consumer ratings. This helps identify games where critics and players have similar or differing opinions.

Average Metacritic Score by Release Year

A line chart illustrates changes in average critic reception over time, helping to identify trends across release years.

Games by Genre

A bar chart compares the number of distinct game titles associated with individual genres. The separate SegaGenres table enables games with multiple genres to appear in each relevant category.

7. Adding Interactive Slicers

I added five slicers to allow users to explore different segments of the dataset.

  • Platform
  • Release Year
  • Developer
  • Genre
  • ESRB Rating

These filters allow visitors to investigate specific platforms, genres, developers, time periods and age classifications.

8. Dashboard Design and Branding

I designed the report using a Sega-inspired blue-and-white colour scheme.

  • Sega blue (#07358C) for the main dashboard background.
  • White and light-grey panels for KPI cards and charts.
  • Blue accents for chart elements and important values.
  • A left sidebar for filters and a structured grid for visualisations.

I retained the same KPI and chart structure as my Nintendo dashboard. This creates a consistent foundation for a future Nintendo vs Sega comparative analysis.

9. Creating an Interactive Web Version

To make the dashboard publicly accessible without requiring visitors to sign into Power BI, I recreated the dashboard using standard web technologies.

  • HTML: Structured the dashboard, filters and visualisation panels.
  • CSS: Reproduced the Sega-inspired design and responsive layout.
  • JavaScript: Managed interactive filtering and recalculated dashboard statistics.
  • Chart.js: Rendered interactive charts.
  • JSON: Stored the game data used by the web dashboard.

The website version allows visitors to interact with the Sega dataset directly through their web browser.

12. Project Limitations and Future Development

The dataset represents the games included in the source file rather than a complete catalogue of every Sega release. Missing review scores may also affect the representativeness of averages. Additionally, some titles appear across multiple platforms, so the interpretation of record-level averages differs from averages calculated per unique title.

A future extension of this project will compare Sega and Nintendo using standardised metrics, common release periods and consistent data-cleaning rules.
