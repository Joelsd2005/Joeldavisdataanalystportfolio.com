Nintendo Game Performance Dashboard

A step-by-step breakdown of the development process, including data preparation, modelling, visualisation, interactivity and deployment.

Project Overview

This project explores the performance of Nintendo video games through descriptive analytics and interactive data visualisations.

The objective was to analyse patterns in critic scores, consumer ratings, gaming platforms, genres and release years.

Tools and Technologies

  • Power BI Desktop
  • Power Query
  • DAX
  • HTML and CSS
  • JavaScript and Chart.js
  • JSON
  • GitHub Pages

Phase 1: Data Collection and Preparation

Step 1: Importing the Dataset

The Nintendo video game dataset contained information including game titles, platforms, developers, genres, release years, Metacritic scores, user scores and ESRB ratings.

  1. Opened Power BI Desktop.
  2. Selected Home, Get Data and Text/CSV.
  3. Imported the Nintendo dataset.
  4. Opened Power Query using Transform Data.
  5. Inspected the dataset before creating visualisations.

Step 2: Cleaning and Transforming the Data

Power Query was used to inspect and prepare the data for analysis. This included reviewing data types, missing values and columns containing multiple categories.

Step 3: Separating Game Genres

One challenge involved games belonging to multiple genres. These were originally stored together in a single field, such as:

['Action', 'Platformer']

A reference query was created from the original NintendoGames table. The genre column was cleaned and split into rows using commas as separators.

This allowed individual genres to be analysed correctly in the Games by Genre chart.

Phase 2: Data Modelling

Step 4: Creating Table Relationships

A unique Game ID was created using an index column in the original NintendoGames table.

The ID was retained in the transformed genre table, allowing the two tables to be connected.

Property Configuration
Primary Table NintendoGames
Secondary Table Genre Reference Table
Matching Field Game ID
Cardinality One-to-Many (1:*)
Cross-Filter Direction Both
Relationship Status Active

Bidirectional filtering allowed genre selections to update the KPI cards and other dashboard visualisations.

Phase 3: Dashboard Development

Step 5: Designing the Layout

A custom Nintendo-themed layout was created using a red-and-white colour scheme.

The dashboard included a title header, sidebar filters, KPI cards and chart panels.

Step 6: Creating KPI Cards

Four KPI cards were created to summarise game performance.

KPI Purpose
Total Games Number of unique game titles
Total Platforms Number of gaming platforms
Average Meta Score Average professional critic rating
Average User Score Average consumer rating

DAX measures and aggregation functions were used to calculate the KPI values.

Step 7: Creating Visualisations

  • Games by Platform: Horizontal bar chart showing the distribution of games across Nintendo platforms.
  • Metacritic Score vs User Score: Scatter plot comparing critic and consumer ratings.
  • Average Metacritic Score by Release Year: Line chart showing changes in average critic scores over time.
  • Games by Genre: Horizontal bar chart showing the distribution of games across individual genres.

Step 8: Adding Interactive Filters

Five dropdown slicers were added to the sidebar:

  • Platform
  • Release Year
  • Developers
  • Genres
  • ESRB Rating

These filters enabled users to explore specific subsets of the Nintendo dataset.

Step 9: Testing Interactivity

Each filter was tested to confirm that the KPI cards and charts responded correctly.

An initial issue prevented the Genre slicer from filtering the entire dashboard.

This was resolved by changing the relationship cross-filter direction from Single to Both.

Phase 4: Web Dashboard Development

Step 10: Creating the Web Version

Public Power BI embedding was restricted on the university account used for the project.

To make the dashboard publicly accessible, its core functionality was recreated using HTML, CSS and JavaScript.

  • HTML provided the page structure.
  • CSS recreated the Nintendo colour scheme and layout.
  • JavaScript handled filtering and KPI calculations.
  • Chart.js rendered the interactive charts.
  • JSON stored the game data used by the application.

The web application used the source CSV data, so some totals differed from those displayed in Power BI.

Step 11: Deploying to GitHub Pages

  1. Created a GitHub repository for the Nintendo dashboard.
  2. Uploaded index.html and games.json.
  3. Opened Settings and Pages.
  4. Selected deployment from the main branch and root folder.
  5. Tested the published website and interactive filters.

Phase 5: Portfolio Integration

Step 12: Creating a Portfolio Page

A dedicated Power BI Projects webpage was created within the existing Data Analyst Portfolio.

The page included a Nintendo project card, a View Dashboard button and a Development Process button linking to this case study.

This allows recruiters and portfolio visitors to explore the interactive dashboard and understand the technical development process.

Project Outcomes and Skills

This project demonstrates practical experience in:

  • Data cleaning and transformation
  • Power Query and data preparation
  • Relational data modelling
  • DAX measures and KPI development
  • Interactive data visualisation
  • Dashboard design and usability
  • HTML, CSS and JavaScript
  • GitHub Pages deployment

The final outcome was an interactive Nintendo dashboard that can be accessed publicly without requiring a Power BI licence or Microsoft account.
